Overview

Your title block, your field names, without a line of custom code.

This module governs how the CAD client and the PLM exchange the properties of a document: which property of the title block corresponds to which field of Odoo, how it is read, and how a corrected value goes back into the file.

No two companies name things the same way. One writes NUMERO PARTE in the title block, another Part No, a third has three properties where a fourth has one, and each CAD has its own conventions on top. Integrations usually solve this with code written for one customer, which becomes the reason nobody dares to upgrade anything.

What it does

A mapping, not a patch

The correspondence between an Odoo field and a CAD property is a record you fill in: the model, the field, the name the property has in the drawing. Adding a property to the exchange is configuration work, done by whoever knows the title block.

Different rules for different people

The procedure the client runs is attached to the user group, so the designers of two divisions, or an internal team and an external studio, can work against the same PLM with the conventions each of them uses.

Read only where it must be

Each mapped property says whether it can be written from the CAD, from the PLM, or from neither. What must be decided by the PLM cannot be overwritten from the drawing, and what belongs to the designer is not touched by the system.

Values pushed back into the files

When a value changes in Odoo, the properties of the affected documents are updated rather than being left to drift, which is what keeps the title blocks telling the truth after a revision.

What changed is written down

Each property update is recorded with its old value, its new value and the CAD property it concerns, so a title block that changed has an explanation and not just a different content.

Language by language

A property can carry a different reference per language, for companies whose drawings travel between plants that do not read the same one.
