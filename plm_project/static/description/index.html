PLM Project

Overview

Project progress measured on the parts, not on an estimate.

Ask how a development project is going and you get a number somebody produced: the frame is seventy per cent, the hydraulics are almost there. It is not dishonest, it is simply the only answer available, because the plan lives in one tool and the parts live in another. Two weeks later the number is still seventy per cent and nobody can say what moved.

When the project and the product share a database the question has a real answer. This module ties the two together: a project knows which components belong to it, and how many of them have actually been released.

What it does

Components belong to the project

Parts are linked to the project they are developed for, and a project shows its own components as a list you can open, rather than as an attachment somebody keeps updated.

Progress that is counted

How many components the project has, and how many of them are released, are computed from the parts themselves. The completion figure follows the engineering state, so it moves when the work moves and not when somebody updates a slide.

Approvals become activities

Confirming and releasing a part generates the activity for whoever has to approve it, attached to the task it belongs to. The approval lands in the inbox of a person, with a deadline, instead of living in a conversation.

Approvals that cannot drift

An activity can be completed only by the user it was assigned to, or by a PLM administrator, and only when the part is in the state the activity is about. What is signed off is what was actually reviewed.

The project with PLM switched on. Plm Complete is not typed in by anyone: it is the share of the project components that have been released, and the tab below lists the components it is computed from, with their engineering state.

The same link seen from the part: which project it is developed for, on the product itself.

Confirming a part creates the approval activity for the person who has to sign it off, and moves the workflow along.

  • ▪  Completion computed from released components
  • ▪  Confirm and release generate approval activities on the tasks
  • ▪  Only the assigned user, or an administrator, can close them
  • ▪  Project, tasks, parts and documents in the same database
