Overview

A first pass of the translation files, produced every night instead of never.

This module translates the translation files of your modules automatically, into the languages you configure, and keeps doing it on a daily schedule.

Translating an interface is work that nobody schedules. A new field is added in English, the Italian and German catalogues fall one string behind, and after a few releases the translated interface is a patchwork where half the labels are in the original language. Starting a translation from an empty file is also the slowest way to do it.

What it does

Configured by path and language

Each entry says which translation files to work on and which languages to produce, so a house module and a customer specific one can be treated differently.

Run every night

A scheduled action goes through the configured entries once a day, so the translations follow the development instead of waiting for somebody to find the time.

The same language is not configured twice

A check prevents the same path from being assigned conflicting entries, which is the mistake that silently produces two translations fighting over the same file.

A starting point, not the final word

What comes out is machine translation: correct enough to work with, and meant to be reviewed by someone who knows the domain. The value is that a translator corrects instead of typing from zero, on a file that is already complete.

  • ▪  Translation files filled automatically in the configured languages
  • ▪  One entry per path, with its own target languages
  • ▪  Run daily by a scheduled action
  • ▪  Machine output, meant to be reviewed before release

Part of OdooPLM, the Product Lifecycle Management suite by OmniaSolutions. It requires the plm module and the python packages googletrans and polib, and it sends the strings to be translated to an external translation service, which is worth knowing before pointing it at confidential wording.
