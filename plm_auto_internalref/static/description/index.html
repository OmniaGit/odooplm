Overview

The internal reference written by the system, the same way every time.

The module automatically fills the internal reference field from the engineering code and the engineering revision of the product. With an engineering code of my_code at revision 0, the internal reference becomes my_code_0.

The internal reference is the string everybody else in the company uses: it appears on orders, on labels, in the warehouse, in the accounting export. When it is typed by hand it drifts — a dash instead of an underscore, the revision forgotten, a space at the end — and every drift becomes a duplicate somewhere downstream.

What it does

Written on creation and on revision

The reference is computed when the product is created and kept in step when it changes, so a new revision does not inherit the reference of the previous one.

One rule, applied everywhere

The same rule applies to every part, which is what makes the reference usable as a key by the systems that read it: the warehouse, the labels, the exports.

The revision is part of the identity

Carrying the revision inside the reference means that two revisions of the same part are two distinguishable items wherever the reference travels, and not the same string with a different meaning.

Changeable when your rule differs

The composition is isolated in a single function meant to be overridden, so a company with its own numbering convention adapts it in a few lines instead of giving up on automation.

  • ▪  Computed on creation and kept in step on revision
  • ▪  Consistent across the whole catalogue
