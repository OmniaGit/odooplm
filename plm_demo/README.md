# PLM Demo Data

A populated PLM environment, so that a fresh OdooPLM install has something to show.

Installing `plm` on an empty database gives you working menus and no data. This
module fills them with a small mechanical product: parts, assemblies, drawings,
3D models, document relations, revisions and the conversations around them.

```bash
# in a container built from https://github.com/OmniaGit/DockerOdooPLM
ODOOPLM_INIT_MODULES=plm,plm_spare,plm_web_3d,plm_demo docker compose up
```

Or from the *Apps* menu of any database that already has `plm`.

> Meant for evaluation, demonstrations and training. Do not install it on a
> production database.

## What gets created

**LSU-100, a linear shaft support unit**: a base plate carrying two bearing units
on a common shaft.

```
LSU-100  Linear shaft support unit
├── BASE-100      Base plate 300x120          ×1
├── BRG-UNIT-001  Bearing unit 30 complete    ×2   (sub-assembly)
│   ├── BRG-HSG-001  Bearing housing 90       ×1
│   ├── BSH-030-001  Bronze bushing           ×1   ─┐
│   ├── SPC-030-001  Spacer ring              ×1    ├ also a spare part BOM
│   ├── SCR-M6-020   Hex screw M6x20          ×4   ─┘
│   ├── CVR-090-001  Bearing cover 90         ×1
│   └── CAP-052-001  End cap 52               ×1
├── SHF-020-001   Drive shaft 30x260          ×1
├── CLP-020-001   Shaft clamp ring 30         ×2
└── SCR-M8-030    Hex screw M8x30             ×8
```

| | |
|---|---|
| Parts | 12, with engineering codes, revisions, materials and weights computed from the solids |
| Bills of material | 3 — two manufacturing BOMs over three levels, one spare part BOM |
| Documents | 30 — a 3MF and a STEP per part, plus DXF and PDF drawing sheets for the machined parts |
| Document relations | 26 — `HiTree` assembly to component, `LyTree` drawing to model, `ExtraTree` model to its STEP export |
| 3D markups | 2 on the top assembly, each with its chatter message linking back to the viewer |
| Chatter | engineering comments on parts and drawings |

Every 3D document is a format the browser viewer renders, so the parts can be
opened and inspected without any CAD tool.

## Where the data comes from

All of it is generated by `tools/generate_demo_geometry.py`, which models the parts
with [cadquery](https://github.com/CadQuery/cadquery), exports STEP and 3MF, draws
the 2D sheets with [ezdxf](https://ezdxf.mozman.at/) and renders the previews with
matplotlib — the same libraries the `plm_automated_convertion` module uses.

That matters for licensing: the geometry is produced by a script in this
repository, owned by OmniaSolutions and published under AGPL-3 like the rest of the
module. **No third party CAD model is redistributed here.** Models downloaded from
community libraries such as GrabCAD are licensed for personal, non-commercial use
and are explicitly non-transferable, so they cannot be shipped in a public
repository — that is why the demo builds its own product.

Regenerating everything, inside the OdooPLM image which already has the libraries:

```bash
docker run --rm --user 0 -v "$PWD":/plm_demo \
    --entrypoint python3 ghcr.io/omniagit/odooplm:19.0 \
    /plm_demo/tools/generate_demo_geometry.py --out /plm_demo
```

It rewrites `data/dataset.json` and `files/`. Change the part catalogue or the
assembly structure at the top of the script and run it again.

`tools/export_demo.py` is the other way round: it extracts a dataset from a live
Odoo database, for building an internal demo from your own data. Anything it
produces is subject to the licensing of the CAD it copies, so think before
publishing it.

## Files

```
data/dataset.json          generated — parts, BOMs, documents, relations, markups
data/curated_chatter.json  hand written demo comments, never overwritten
files/documents/           STEP, 3MF, DXF and PDF payloads
files/previews/            document thumbnails
files/images/              product images
files/markups/             background image the 3D markups are drawn on
tools/                     the generator and the database exporter
hooks.py                   builds everything through the ORM at install time
```

## How it is loaded

`post_init_hook` creates the records through the ORM. Documents are created with
the `odooPLM` context, exactly like the CAD client does, so they are flagged as PLM
documents (`is_plm`) and are visible through the PLM record rules — created without
it they would be plain attachments and every PLM view would look empty.

Every record is registered with an external id, so uninstalling removes the demo
data. The uninstall hook takes the records down in dependency order — BOMs, then
markups, then document links and relations, then documents, then parts — because
`plm` rightly refuses to delete a document another one still references.

Installing twice is harmless: records that already exist are left alone.

## Where to look in the interface

The PLM app has its own menu, and that is where the document tabs live:

* **PLM → Components** — the parts, each with its Linked Documents tab
* **PLM → Documents** — the documents, with previews and relations
* Open a `.3mf` document and use the 3D viewer; on `LSU-100.3mf` the two markups
  are waiting in the chatter

*Inventory → Products* shows the same parts through the standard Odoo form, which
does not carry the PLM document tab.
