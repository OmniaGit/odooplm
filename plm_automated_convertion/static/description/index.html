Automated CAD Conversion

Overview

Every drawing readable by everyone, without an engineer exporting it.

A native CAD file is useful to the three people who own a licence for that CAD. Everyone else — purchasing sending a drawing to a supplier, the shop floor reading a sheet, a customer asking for a model — needs a PDF, a STEP or a picture. So somebody in the technical office spends an afternoon exporting files by hand, and does it again after the next revision, and forgets one.

This module removes that afternoon. You describe once which format has to become which, and the conversion happens on its own, in the background, on the revision that is current.

What it does

Rules, not clicks

A conversion rule says what turns into what — a starting format, a resulting format — and can be limited to a product category, so castings are treated differently from sheet metal. The name of the produced file follows a rule of yours, not a default.

A queue you can look into

Every conversion is a line in a queue, with its source document, the document it produced, its state and, when something goes wrong, the error. Nothing is lost silently, and a failed job can be sent back in.

Conversion servers

The heavy work is delegated to the machines that own the CAD licences. Each server is declared with its address and its timeout, jobs are distributed to it, and a hung CAD process can be recovered instead of blocking the queue.

It runs by itself

A scheduled action empties the queue on its own, so the conversions happen at night and the results are there in the morning. They can also be triggered by hand on a selection of documents, when something is urgent.

The formats it produces

PDF for the drawing that goes to a supplier, STEP for the model a customer can open in any CAD, STL and 3MF for the web viewer and for printing, DXF for the 2D sheet, PNG for the preview that makes a product recognisable in a list. Formats beyond these are reached through a CAD exchange installation, when one is available on the conversion server.

  • ▪  Conversion rules by format and by product category
  • ▪  A queue with states, results and errors, per document
  • ▪  Work distributed to the machines that hold the CAD licences
  • ▪  Scheduled overnight, or started by hand when it is urgent

Part of OdooPLM, the Product Lifecycle Management suite by OmniaSolutions. It requires the plm module and a few python packages for the local conversions — cadquery, ezdxf, matplotlib, numpy-stl and to-3mf — which the OdooPLM Docker image already carries. Released under AGPL-3.
